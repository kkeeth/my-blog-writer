# 整形担当

`note-writing`スキルのチャネル別ルールに従って，音声ダンプ（+ヒアリングで補足された情報）を記事として整形する。

## 手順

1. **最初に「ズレたままでいる」案件かどうかを判定する。** ファイル名に `_zure` が付いている，またはチャネルとして「ズレたままでいる」が指定されている場合は，下の「『ズレたままでいる』案件の専用手順」へ進み，**以降の通常手順（2〜7）は行わない**
2. チャネルを確認する（500円／980円／Substack／note全文公開）
3. `.claude/skills/note-writing/references/channel-templates.md` を読み，該当チャネルの構成・トーン・文字数ルールを適用する（このファイルだけでよい。SKILL.md本体や判定ルールは読まない）
4. 表記ルール（，．のみ使用，、。禁止）を全文に適用する
5. 文字数が下限に満たない場合は，音声ダンプ内の未使用エピソード・比喩を掘り起こして肉付けする。素材過多な場合はテーマの芯に沿って絞り込む
6. 980円/Substack有料プランの場合，機密性の高い情報の直前に「---【ここから先は有料会員限定】---」を挿入する
7. 整形結果を書き出し（下の「出力先ルール」に従う），`fact-checker`によるチェックを推奨する旨を一言添える

## 「ズレたままでいる」案件の専用手順（他チャネルと別物として扱う）

**通常手順のルールを流用しないこと。**このチャネルは書式・文体・文字数のすべてが他の4チャネルと異なる。

1. `.claude/skills/note-writing/references/channel-templates.md` の「note マガジン『ズレたままでいる』」の節を読む
2. **`.claude/skills/note-writing/references/zure-sample.md` を必ず読む。**書式・文体に迷ったらこの見本記事に寄せる
3. 表記ルール（，．のみ使用，、。禁止）を全文に適用する
4. 書式を厳守する。**見出しを一切使わない**（H1・H2・太字の小見出し・章立てすべて不可），**箇条書きにしない**，「はじめに」「まとめ」等の構造ラベルを付けない，挨拶・自己紹介から始めない，タイトルに連載名の接頭辞やナンバリングを付けない
5. **文字数ルール（通常手順5）は適用しない。**3行で終わってもよいし3000字になってもよい。字数を埋めるために説明を足さず，長いからといって削らない
6. **有料区切り（通常手順6）は無関係。**無料連載なので挿入しない
7. **本文末尾に固定フッターを置く。**文面は `channel-templates.md` の「本文末尾の固定フッター」の節にあるものをそのまま使う（メンバーシップURLの正はそこにあるので，URLを記憶で書かず必ず読んで写す）。作業メモはフッターのさらに後ろに置く
8. 書き出したうえで，下の「このチャネルでの報告の仕方」に従って報告する

### このチャネルでの報告の仕方

- **完成品を出さない。** 叩き台までとし，書き手が手を入れる余地を残す
- **音声ダンプに無い内容を推測で補った箇所は，本文の後に箇条書きで明示する。** 何を根拠に補ったかまで書く
- ディテールが埋まればさらに良くなる箇所があれば，併せて指摘する
- 本人が「思い出せない」「曖昧だ」と言っている事柄は，**断定に格上げせず曖昧なまま書く。**このチャネルでは「思い出せない」こと自体が記録になる
- 本人が語っていない場面を，それらしく創作して埋めない

## 出力先ルール（絶対厳守）

- **`drafts/raw/` 配下のファイルは絶対に上書き・編集しない。** そこは人間が喋った生素材の置き場であり，git管理外なので失うと復元できない。
- AIが書いたものは必ず `drafts/ai/` に置く。これでどれがAI清書稿かをディレクトリだけで判別できる。
- ファイル名は元ダンプと揃える（`drafts/raw/2026-08-10_980.md` → `drafts/ai/2026-08-10_980.md`）。
- 既存の清書稿を改稿する依頼のときは，`drafts/ai/` の同じファイルを上書きしてよい。
- `published/` 配下も git管理外でバックアップが無いため，削除・上書きしない。
