# my-blog-writer

KEETHさんのブログ・ニュースレター執筆用ワークスペース．音声ダンプを note / Substack の記事に仕上げるまでの「ヒアリング → 整形 → ファクトチェック」を Claude Code 上で回す．

ネタ出し（週次執筆プラン）は Cowork 側のスケジュールタスクで行うため，ここでは扱わない．

## 使い方

### 0. 準備

このリポジトリのルートで Claude Code を起動する．

```bash
cd my-blog-writer
claude
```

`CLAUDE.md` とスキル・サブエージェントは自動で読み込まれる．

### 1. 音声ダンプを置く

`drafts/` 配下に音声ダンプを Markdown で保存する．ファイル名はチャネルが分かる形にする．

```
drafts/2026-08-10_980.md      ← note 980円プラン向け
drafts/2026-08-10_500.md      ← note 500円プラン向け
drafts/2026-08-10_substack.md ← Substack向け
drafts/2026-08-10_free.md     ← note全文公開（無料）向け
drafts/2026-08-10.md          ← チャネル未定（提案してもらう）
```

中身は整形不要．喋ったままの文字起こしでよい．

### 2. 整形を依頼する

チャネルが決まっていれば明示する．

```
drafts/2026-08-10_980.md を980円プランで整形して
```

**決まっていなければ指定しなくてよい．** その場合，ダンプの中身から最適なチャネルを評価して提案してくれる．

```
drafts/2026-08-10.md を整形して
```

いずれの場合も Claude は**すぐに整形せず，先に確認を返す**．

### 3. チャネル提案とヒアリングに答える

返ってくるのは次の2つ．

**チャネル提案**（未指定のときのみ）：機密性の高さ・専門性・素材の濃さから，第一候補と理由，あれば第二候補が提示される．

```
第一候補：980円プラン
家族との具体的なやり取りと，業界の風潮への率直な違和感が芯にあるため．
第二候補：Substack
コーチングの専門性を軸に据え直すなら，エッセイとしても成立する．
```

**ヒアリング**：「感動した」「モヤっとした」のように感情・評価だけが語られ，理由や背景が言語化されていない箇所を1〜3個ピックアップして質問してくる．口語で答えるだけでよい．そのまま素材として使われる．

```
980円で．モヤっとしたのは，相手が善意でやってるのが分かるからで，
だからこそ断る理由を作れなかったのが自分でも嫌だった
```

チャネルを明示して依頼した場合でも，内容と明らかにミスマッチなときだけ別チャネル案が一言添えられる．理由・背景が音声ダンプの時点で十分語られていれば，ヒアリングは省略される．

### 4. 整形結果を受け取る

`formatter` がチャネル別テンプレート・トーン・文字数ルールに沿って本文を作る．980円プラン／Substack有料想定の場合は，機密性の高い情報の直前に `---【ここから先は有料会員限定】---` が挿入される．

### 5. ファクトチェックする

```
ファクトチェックして
```

`fact-checker` が本文中の検証可能な事実（歴史的事実・数値・作品設定など）だけを Web 検索で確認し，誤りがあれば訂正案と出典を出す．個人の体験・感情・解釈はチェック対象外．

### 6. 確定・公開

最終稿を `drafts/` 内で確定し，公開後に `published/` へ移す．

**公開は手動で行う．自動投稿・自動送信は一切しない．**

## チャネル早見表

| チャネル | 位置づけ | こんな素材なら | 文字数目安 | 目標 |
| --- | --- | --- | --- | --- |
| note 980円 | 表では言えない凡人の本音．率直な意見・解釈 | 個人が特定されうる話，家族・信条など機密性の高い話，他者や業界への率直な批判 | 2500〜4000字 | 月3本 |
| Substack | 独自トーンのエッセイ．ストーリー＋専門性 | 技術・キャリア・コーチングなど専門性を，個人のストーリーと織り交ぜて語れる | 2000〜3500字 | ー |
| note 500円 | 真面目な本音の共有場．気づき・体験を誠実に | 等身大の失敗談・学び．機密性は高くないが読者が共感しやすい | 1500〜2000字 | 月3本 |
| note全文公開 | 集客用．軽めの気づき系．メンバーシップ導線 | 気づきが1つに絞れる軽い話．素材が薄いときの受け皿にもなる | 800〜1200字 | ー |

上から順に見て，最初に強く当てはまったものが第一候補．判定はこの順序で行われる．構成・トーンの詳細は `.claude/skills/note-writing/SKILL.md` を参照．

## 表記ルール（絶対厳守）

句読点は「、」「。」を一切使わず，必ず全角カンマ「，」と全角ドット「．」を使う．見出し・本文問わず全文に適用する．全チャネル共通．

## サブエージェント

| エージェント | 役割 | 呼ばれるタイミング |
| --- | --- | --- |
| `hearing-agent` | チャネルを提案し，理由・背景が未言語化の感情表現を拾って問い返す | 「整形して」の直後 |
| `formatter` | チャネル別テンプレートで本文を整形する | ヒアリング完了後 |
| `fact-checker` | 検証可能な事実のみ Web 検索で確認する | 整形完了後 |

明示的に指名して呼ぶこともできる．

```
hearing-agent で drafts/2026-08-10_980.md を見て
```

## ディレクトリ構成

```
.claude/
  skills/note-writing/SKILL.md   ← チャネル別ルール本体
  agents/
    hearing-agent.md             ← ヒアリング担当
    formatter.md                 ← 整形担当
    fact-checker.md              ← ファクトチェック担当
CLAUDE.md                        ← ワークスペース全体の指示
drafts/                          ← 音声ダンプ・整形中の原稿
published/                       ← 公開済み原稿の控え
```

## 運用上の注意

- 各サブエージェントは目的が明確なタスクのみに使う．1回の依頼で完結しない場合は，無限にリトライせず途中経過を報告して次の指示を待つ．
- 自動投稿・自動送信は行わない．
- トークン消費が想定より大きくなっていないか，長い作業の前後で確認する．
